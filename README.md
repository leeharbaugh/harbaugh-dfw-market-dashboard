## Market Notes (AI-generated narrative)

The "Market Notes" panel on the dashboard is generated by OpenAI from
the current dashboard data. It is intentionally global (one shared
document, not per-user) and is **never** generated on page load or on
a normal "Refresh Data" click. Generation only runs in two ways:

1. **Monthly cron** — `vercel.json` schedules
   `GET /api/generate-market-notes` to run on the 25th of each month
   (after TRERC has typically published updated monthly data).
2. **Protected manual refresh** — visit
   `/api/generate-market-notes?secret=YOUR_MARKET_NOTES_SECRET`
   to regenerate on demand.

The dashboard page reads whatever was last saved in shared storage. If
no notes have been generated yet, a graceful fallback message is shown.

### Required environment variables

| Variable                  | Purpose                                                                                                                                                                                       |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OPENAI_API_KEY`          | Server-only OpenAI key. Used exclusively by `lib/market-notes/*`.                                                                                                                             |
| `MARKET_NOTES_SECRET`     | Shared secret for the protected manual refresh URL.                                                                                                                                           |
| `CRON_SECRET`             | Vercel Cron's bearer token; used to authenticate the scheduled job. Set this in Vercel Project Settings → Environment Variables, and Vercel will inject it into cron triggers automatically. |
| `BLOB_READ_WRITE_TOKEN`   | Vercel Blob token. Set automatically when you connect a Blob store to the project under **Storage → Blob**. Required for the production storage adapter.                                      |
| `OPENAI_MODEL` _(opt.)_   | Override the default OpenAI model (`gpt-4o-mini`).                                                                                                                                            |
| `MARKET_NOTES_FILE` _(opt.)_ | Force the filesystem adapter at a specific path (otherwise defaults to `.market-notes/current.json` in dev).                                                                               |

### Storage adapter

Market Notes are persisted via the adapter in `lib/market-notes/storage.ts`.
Adapter selection (first match wins):

1. **Vercel Blob** when `BLOB_READ_WRITE_TOKEN` is set. This is the
   production path. The record is stored as a single stable blob at
   `market-notes/current.json` (no random suffix, overwrite allowed)
   and read via `head()` + `fetch(..., { cache: "no-store" })` so the
   dashboard always sees the freshest copy.
2. **Filesystem** when `MARKET_NOTES_FILE` is set, or in non-production
   (defaults to `.market-notes/current.json`). Used for local dev.
3. **In-memory fallback** otherwise. Survives only the lifetime of a
   single server process — logs a warning so it's obvious in production
   that real storage still needs to be wired in.

### One-time Vercel setup

1. In your Vercel project: **Storage → Create → Blob**. Connect the
   new store to the project. Vercel will populate
   `BLOB_READ_WRITE_TOKEN` in the project environment automatically.
2. Add `OPENAI_API_KEY`, `MARKET_NOTES_SECRET`, and `CRON_SECRET` to
   **Settings → Environment Variables**.
3. Deploy. The monthly cron declared in `vercel.json` will write the
   first record; you can also kick it off immediately by visiting
   `/api/generate-market-notes?secret=…`.

## FRED data cache (assembled registry)

FRED metrics are loaded from a **single pre-assembled registry** stored in
shared persistence (same Blob store as Market Notes). This avoids firing
14 parallel FRED API calls on every page view.

### Behavior

| Path | FRED source |
| ---- | ----------- |
| **SSR / normal page load** | Fresh cache if younger than 6 hours; otherwise live fetch + persist |
| **Refresh Data** (`?refresh=1`) | Live FRED fetch + cache update |
| **Cron** (`/api/refresh-fred-cache` every 6 hours) | Live fetch + cache update |

If a live refresh fails but a stale cache exists, the dashboard serves the
stale cache rather than failing entirely.

### Cron and manual warm

`vercel.json` schedules `GET /api/refresh-fred-cache` every 6 hours.
Authenticate the same way as Market Notes:

- Vercel Cron: `Authorization: Bearer ${CRON_SECRET}`
- Manual: `/api/refresh-fred-cache?secret=${FRED_CACHE_SECRET}` (or `MARKET_NOTES_SECRET`)

### Optional environment variables

| Variable | Purpose |
| -------- | ------- |
| `FRED_CACHE_SECRET` | Manual cache refresh URL secret (optional if `MARKET_NOTES_SECRET` is set). |
| `FRED_CACHE_FILE` | Force filesystem cache path in dev. |
| `FRED_CACHE_MAX_AGE_SECONDS` | Override cache TTL (default: 21600, same as FRED fetch revalidate). |
| `FRED_CACHE_DISABLED` | Set to `1` to always fetch live (debugging). |

Blob pathname: `fred-cache/registry.json` (private).
